# Governance

## Current Stage

Agentrail is in pre-GA development, maintained by its founding team. The project welcomes community contributions and aims to grow toward a broader contributor model over time.

## Decision Making

The project currently operates under a **founding maintainer model**:

- The founding maintainer ([yai-dev](https://github.com/yai-dev)) holds final decision authority on architecture, API design, and release timing
- Community input is actively sought and taken seriously
- Decisions on significant changes are made transparently via GitHub Issues and Discussions before implementation

For day-to-day changes, any approved PR merged to `master` represents an accepted decision.

For significant API changes, breaking changes, or new major subsystems, a discussion issue should be opened first to gather feedback before a PR is submitted.

## Roles

### Users

Anyone using Agentrail packages. Contributions welcome via Issues, Discussions, and PRs.

### Contributors

Anyone who has had one or more PRs merged. Contributors are credited in release notes via Changesets.

### Maintainers

Maintainers have write access to the repository and participate in release decisions. Currently the founding team. A path to maintainership will be documented here as the project matures toward 1.0.

## Roadmap Influence

Community members can influence roadmap priorities by:

1. Opening a [feature request](https://github.com/yai-dev/agentrail/issues/new?template=feature_request.md) or starting an [Ideas discussion](https://github.com/yai-dev/agentrail/discussions)
2. Referencing [ROADMAP.md](ROADMAP.md) items in issues and PRs
3. Submitting PRs for roadmap items — mention the relevant roadmap section in the PR description

## Changes to Governance

This document will be updated as the project grows. Proposed changes to governance should be raised as a GitHub Discussion before being applied.
